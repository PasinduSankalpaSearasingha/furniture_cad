# Engineering limits and outstanding work

The application now includes an integrated React, Astra/Sunburst, CAD and Blender studio; see [current implementation](INTEGRATED_STUDIO.md) and [verification](STUDIO_VERIFICATION.md). It is **not a qualified factory manufacturing system**. Production release remains unavailable: validation reports contain unwaivable blockers, and the release endpoint refuses a REVIEW package even if someone changes database state. Older implementation notes below describe earlier milestones where applicable.

Implemented: cabinet parametric geometry and stable IDs; explicit local/assembly transforms; registry-based finished/blank dimensions; evidence-referenced material snapshots; paired cardinal blind-dowel geometry with fit/alignment checks; STEP, metre-correct GLB and union STL exports; CAD-derived orthographic and part review DXFs/PDF; CSV/XLSX/JSON cut/glass/hardware schedules and material-volume BOM; classified findings; SQLAlchemy catalogs, users, projects, revisions, jobs, review records and audit events; authentication, roles, private file delivery and hashes; Celery dispatch, status, manual retry and administrative failed/stale-job recovery; Alembic migrations; dependency lock; Compose and CI configuration.

Incomplete engineering:

- Factory-approved profiles and physical benchmark evidence were not provided. Test profiles are synthetic, explicitly named test fixtures. Material approvals represent catalog assertions with evidence references, not independently certified facts.
- Paired dowel holes, confirmat clearance/pilot bores and rectangular dado/rabbet/mortise-tenon receiving pockets with matching integral tenons now have actual CAD geometry, fit checks and derived stock envelopes. Prismatic joints need explicit cross-section and depth profiles. Unsupported/incomplete profiles remain blocked, and door-frame joints are still incomplete. These geometry checks do not establish safe residual walls, complete connection coverage, assembly strength or load capacity. Photo-plan machining features remain unverified. Demo dowels always block approval.
- Door frame remains butt-connected review geometry. Back fastening, glazing rebates/retainers/seals, verified glass cut size, hardware mounting features and hinge-motion/collision analysis are absent. Glass is visualization only. No verified hardware schedule can be supplied without genuine manufacturer/factory data; the sample schedule is empty and blocked.
- Drawings project exact CAD edge geometry and exact envelope dimensions, with sampled curves. They have no hidden-line removal, sections, exploded assembly, hole tables, joint details, dimension tolerances or approved shop templates. They are REVIEW documents. No FreeCAD TechDraw integration is claimed.
- No per-edge banding/deductions, sheet nesting, kerf constraints, wastage procurement, stock count, database-managed prices, labour, finishing or packaging costing. Edge treatment and grain are recorded profile data; wood movement is not calculated. BOM blank area/volume is traceable; purchase quantities and costs remain null with explicit required-data statuses.
- No structural, stability, glass safety or machine safety certification. No CNC/CAM output. See BENCHMARK.md for factory qualification inputs and protocol.

Incomplete product/infrastructure:

- A separate estimated two-section decorative study is available through `CabinetSpec.display_layout`; see IMAGE_STUDY.md. Its 55 components, glazing, stepped mouldings and simplified ornament silhouettes are actual CAD but are manually parameterized approximations. It cannot enter the verified basic AI template flow or claim physical verification. Original carved profiles, handles/hinges, construction, glazing retention and machining details are not reconstructed from the photograph. This does not implement unrestricted image-to-CAD generation.

- Image upload, OpenAI Responses/Structured Outputs, specialist collaboration, private image-generation APIs and measured-specification verification are implemented; see AI_WORKFLOW.md. Forma Studio provides a responsive project dashboard, design forms, measured verification, engineering review, catalog entry and a complete private file browser; see WORKSPACE_UI.md. The file browser displays actual generated GLB geometry with orbit/zoom, DXF/PDF drawings, workbook sheets, tables, reports and images. The studio's dimension illustrations remain separate from this CAD viewer. The furniture library adds 43 common review templates with estimated AI parameters and curved geometry; see FURNITURE_LIBRARY.md. These are bounded visual/construction studies, not engineered manufacturing templates for every furniture type. No arbitrary furniture reconstruction is claimed.
- A live estimated chair design/review run completed with the configured models; see FURNITURE_LIBRARY.md and IMPLEMENTATION.md. This single run does not qualify vision accuracy, multi-image quality, image-tool compatibility, photorealism or reconstruction fidelity. Automated tests mock OpenAI; the real-SDK HTTP adapter uses an in-process mock transport. The provided demonstration uses a CAD-derived reference, mock AI responses and synthetic designer input. The furniture extension used the existing chair photograph observations for its live estimate; physical measurements and live presentation-image generation remain unqualified. Set backend models/key explicitly and opt into live evaluation before relying on AI outputs.
- Orchestration uses deterministic Python, not the separate OpenAI Agents SDK. The orchestrator has local durable stage/event/invocation records; no external Agents SDK trace viewer is integrated. In-process schema/tool validation, bounded correction passes and hash checkpoints prevent automatic authority promotion, not all possible model misinterpretation.
- AI usage totals cover known provider responses. Configured price snapshots yield estimates; unavailable rates or unknown usage after timeouts/crashes yield null totals. There is no invoice reconciliation, enforced monetary spend cap, transactional outbox or exactly-once external billing guarantee. A crash after an external response and before checkpoint commit can repeat a request on explicit retry. Administrative stale-workflow recovery is provided; unattended reconciliation remains incomplete.
- Immutable specifications and append-only review records are enforced by the API; artifact tampering is detected with hashes. Database/storage administrators remain trusted. There is no database-level WORM storage, signed external timestamping or legal-grade tamper-proof audit service. Production shop-package generation and a successful real release are not implemented or tested.
- Bearer sessions expire and can be revoked. External identity federation, MFA, account lockouts and rate limiting are not included. Put TLS, rate/connection limits, request deadlines and organizational identity controls in front of any exposed installation. No anonymous file serving or public static outputs mount is configured.
- PostgreSQL and Redis/Celery services are configured but were not launched locally because the Docker engine was stopped. Local integration tests use SQLite with eager or actual background execution. The password-free local workspace uses a tested bounded, serial in-process executor without Redis. Its API must run as a single process; use Celery for shared deployments. CI configurations are provided but have not run on a remote CI service. Linux CAD wheels/container execution still need deployment verification.
- Queue dispatch is not a transactional outbox. A crash between DB commit and queue submission, or a worker death after claim, can leave stale jobs. Local background work drains during graceful shutdown, but queued tasks do not survive forced process termination. Stop workers, recover stale jobs administratively, restart and retry into a new job directory. There is no distributed lease, automatic crash reconciliation, unattended retention scheduler or object-store adapter. Windows Celery uses the solo pool; process time limits are not enforced by solo.
- Application dependency versions and hashes are locked. Container base tags and CI actions still require your registry pinning/security maintenance policy. Backup/restore procedures are documented, not automatically scheduled or restore-tested here.

Do not remove blockers simply to enable release. Complete the missing geometry, documents, checks and factory benchmark first, then qualify a manufacturing package generator and its release tests against controlled approved inputs.
